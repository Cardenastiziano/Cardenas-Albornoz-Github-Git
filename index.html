Repositorios Locales & Remotos

Tu copia local te brinda independencia total para experimentar sin conexión a red, mientras que el repositorio en GitHub unifica y resguarda el trabajo del equipo.

Tip: git remote -v para auditar tus conexiones.
🔀

Estrategias de Ramas (GitFlow)

Trabajar en ramas de características (feature/) aísla el desarrollo, asegurando que la rama principal main permanezca limpia y siempre lista para producción.

Tip: git switch -c para crear ramas rápidamente.
⚡

Commits Atómicos & Descriptivos

Cada confirmación debe contener una única unidad lógica funcional. Un historial limpio simplifica el rastreo con git bisect y la auditoría de cambios.

Tip: Usa mensajes imperativos en tus commits.
Paso a Paso

Flujo de Trabajo Estándar

El ciclo recomendado para colaborar en equipo sin pisar código ajeno

1

Actualizar main

Sincroniza los últimos cambios antes de comenzar una nueva tarea: git pull origin main.

2

Crear Branch

Crea tu rama de trabajo con un nombre descriptivo: git switch -c feature/mi-modulo.

3

Commits Frecuentes

Guarda tus avances de forma atómica y ordenada: git commit -m "feat:...".

4

Integrar & Merge

Integra el resultado a main tras verificar que todo compila y funciona correctamente.

Referencia Rápida

Comandos Esenciales en Terminal

Las instrucciones fundamentales utilizadas en este trabajo práctico

Clonación inicial Setup
git clone https://github.com/...

Descarga el repositorio completo con todas sus ramas e historial de commits a tu máquina local.

Ramificación limpia Branches
git switch -c feature/estilos-mejoras

Crea de inmediato una rama aislada para desarrollar mejoras sin tocar el código estable.

Confirmación atómica Commits
git commit -m "Mejorar estilos visuales..."

Registra en el historial los cambios preparados con una descripción comprensible.

Fusión y despliegue Integration
git merge feature/estilos-mejoras

Incorpora de manera segura los cambios desarrollados en la rama a la línea principal main.
